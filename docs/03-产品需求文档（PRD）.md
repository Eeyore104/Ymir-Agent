## 一、产品概述

### 1.1 产品定位

ymir-agent 是一个**多 Agent 协作的软件开发平台**：用户输入一条自然语言需求，平台调度四个 AI 角色（产品经理 / 架构师 / 工程师 / QA）按标准作业程序（SOP）协作，依次产出 PRD、架构设计、可运行代码与四维评测报告；全程人工可在关键节点审批与驳回，所有产物统一版本管理。

> 一句话：**把一句需求，变成一套经过评审、评测、可导出的完整软件交付物。**

### 1.2 产品目标（三重定位）

| # | 目标 | 说明 |
|---|---|---|
| G1 | 面试旗舰作品 | AI Agent 方向求职代表作：自研编排内核 + 评测体系 + 成本控制，均有可讲的技术叙事 |
| G2 | 个人真实使用 | 日常原型/小工具开发入口：需求 → 代码 → 评测一条龙，减少重复劳动 |
| G3 | 创业内部工具底座 | 未来垂直行业 SaaS 的内部研发工具，验证多 Agent 协作范式 |

### 1.3 成功指标（v1.0）

| 指标 | 目标值 |
|---|---|
| 全流程可跑 | 浏览器内完成「需求 → PRD → 架构 → 代码 → 评测」一次完整运行 |
| 审批可用 | 三关审批均可通过/驳回；驳回后产物版本递增且带反馈重跑 |
| 评测可信 | 四维分数 + 证据链 + 双门槛通过判定 |
| 成本可控 | 单 run token 上限 50 万、日成本上限 ¥50（默认，可配），超限自动暂停 |
| 工程可信 | CI 绿（ruff + pytest）、e2e 绿、一键启动可复现 |

### 1.4 术语表

SOP（标准作业程序，此处指可配置的流水线定义）、关卡 Gate、HITL（Human-in-the-Loop）、Artifact（产物）、planner/executor（规划/执行模型分级）、ACI（Agent-Computer Interface）、A2A/MCP。完整术语表见架构设计附录 B。

## 二、目标用户与核心场景

### 2.1 目标用户

- **主用户**：用户本人（Python 方向开发者，单人使用，本机部署，单租户）
- **次要读者**：面试官（作品叙事）、未来协作者（开源社区，v2.x）

### 2.2 用户故事

| # | 用户故事 | 对应功能 |
|---|---|---|
| US-01 | 我输入一句需求（如"做一个待办事项 REST API"），选择流水线与模式发起运行，然后离开浏览器，回来看到 PRD 初稿 | F2 / F3 / F9 / F10 |
| US-02 | 我在审批中心看到 PRD 关卡卡片，阅读 Markdown 渲染的 PRD；不满意时写反馈驳回，PM 角色带反馈重跑出新版本 | F4 / F5 |
| US-03 | 设计评审通过后，工程师角色在 Docker 沙箱里写代码并冒烟执行，我在消息流里看到全过程 | F3 / F8 / F10 |
| US-04 | 运行结束后，我收到四维评测报告（需求符合度 / 可运行率 / 规范 / 架构合理性），每一分都附证据链 | F6 |
| US-05 | 我对两个产物版本做 diff，满意后导出 zip 存档 | F5 |
| US-06 | 我想验证「贵模型规划 + 便宜模型执行」是否划算：用批量模式对同一需求跑不同模型组合，看性价比榜单 | F6 / F7 |

## 三、产品范围

### 3.1 v1.0 范围（P0）

四角色 SOP 流水线（需求 → PRD → 架构 → 代码 → 评测）+ HITL 三模式审批 + 产物库（版本/diff/导出）+ 四维评测 harness + 模型网关（分级路由 + 预算 + 计量）+ Docker 沙箱 + REST/SSE API + Vue3 Web 控制台。

### 3.2 v1.0 明确不做

| 不做的事 | 理由 | 归属版本 |
|---|---|---|
| 多租户 / RBAC / 登录 | 单租户个人使用 | v2.x |
| 部署落地（生成制品并实际部署） | 先证明「生成 + 评测」核心价值 | v2.0 |
| JetBrains 插件 | Web 控制台先行 | v1.1 |
| 可视化画布编排流水线 | YAML 声明式已可配置化 | v1.x |
| 移动端 | 单人 PC 工具 | 不做 |
| Java / Spring Boot 代码生成模板 | 用户确认 Python 优先（见 §9-D5） | 暂不排期 |
| 多 run 并行 | 单用户串行足够 | v1.x |

### 3.3 版本演进总览

| 版本 | 周期 | 目标 | 核心范围 |
|---|---|---|---|
| **v1.0** | W1-10 | 面试旗舰 MVP | 四角色全流程 + 三关审批 + 产物库 + 四维评测 + Web 控制台 |
| **v1.1** | +4-6 周 | IDE 协同 | JetBrains 插件：IDE 内触发 / 侧边栏进度 / 原生 diff 审批 / 上下文注入 |
| **v1.2** | +4-6 周 | 垂直场景模板库（Python 生态优先） | FastAPI+Vue3 全栈模板（首选）、Python CLI/自动化工具模板；增量 patch 生成 + diff 人审；GitHub 推送导出 |
| **v2.0** | +6-8 周 | 部署落地 | Dockerfile / compose / K8s 制品生成；本地 compose up 与远程 SSH 部署；部署成功率评测维度 |
| **v2.x** | 持续 | 平台化 / 商业化 | 多租户 + RBAC + 审计；MCP 工具生态；A2A 跨平台协作；模板市场 |

## 四、功能需求（P0）

> 每条需求的实现依据见架构设计（章节号标注）；验收标准均为**可演示**判据。

### F1 项目管理

| ID | 需求 | 验收标准 |
|---|---|---|
| F1.1 | 创建 / 查看项目（name, description） | API 可建项目、查项目；Web 项目看板可见 |
| F1.2 | 项目详情聚合（runs / artifacts / 最近评测概览） | 项目页一屏可见三类信息 |

### F2 流水线运行与编排

| ID | 需求 | 验收标准 |
|---|---|---|
| F2.1 | 发起运行：输入 requirement，选择 pipeline（默认 `software-dev` v1.0）与 mode（key_node / batch / debug） | POST 返回 202 + run_id |
| F2.2 | 状态机驱动：pending → running → waiting_approval → completed / failed / paused | 状态迁移全部落库，UI 实时可见 |
| F2.3 | 运行控制：pause / resume / cancel / retry-stage | 四个动作均生效且留事件记录 |
| F2.4 | SOP 声明式配置（`config/pipelines/*.yaml`：阶段 / 角色 / 输入输出 / 关卡 / 转移边）+ 加载时静态校验 | 改 YAML 即改流程，不改代码；非法定义被校验器拒绝 |

### F3 四角色运行时

| ID | 需求 | 验收标准 |
|---|---|---|
| F3.1 | 角色 YAML 定义（tier / capabilities / inputs / outputs / output_schema / retry），放入 `config/roles/` 即注册 | 新增角色无需改代码 |
| F3.2 | pm：需求 → PRD，输出过 `PRDDocument` 结构化校验 | 命令行单跑 PM 产出 PRD v1 入库 |
| F3.3 | architect：PRD → 设计文档（模块划分 / 选型 / 接口草案 / 目录结构） | 产物过 schema 校验 |
| F3.4 | engineer：PRD + 设计 → 代码，在沙箱工作区写文件 + 冒烟执行 | 代码产物落盘成版本；沙箱 exec 通过 |
| F3.5 | qa：调度评测 harness，汇总解读评测报告 | 报告产物入库 |
| F3.6 | 角色间结构化消息（文档先行：消息承载产物引用 + ≤500 字摘要） | 消息流面板可见完整链路 |

### F4 HITL 人工审批（三模式同一套机制）

| ID | 需求 | 验收标准 |
|---|---|---|
| F4.1 | 策略三模式：key_node（三关阻断：PRD 确认 / 设计评审 / 代码合并前）/ batch（全自动、仍落库审计）/ debug（每阶段人审） | 三模式行为符合定义；batch/debug 有单测覆盖 |
| F4.2 | 审批卡片：阶段摘要 + 待审产物（PRD/设计 Markdown 渲染；代码文件树/diff）+ 历史反馈链 | 审批中心可见完整上下文 |
| F4.3 | 驳回回退：reject 沿 `on_reject_target` 回退，feedback 以消息进入角色上下文，attempt+1 重跑，产物出新版本 | 驳回后版本递增；重跑输入含历史反馈 |

### F5 产物库与版本管理

| ID | 需求 | 验收标准 |
|---|---|---|
| F5.1 | Artifact / ArtifactVersion 模型：内容进文件系统、元数据 + hash 进库；版本不可变、带血缘（parent_version） | 再生成必为新版本；历史永久可溯 |
| F5.2 | diff：逐文件 unified diff，前端按文件分组渲染 | `/artifacts/{id}/diff?from=&to=` 可用 |
| F5.3 | zip 导出：整库导出（PRD/设计/代码/评测报告 + manifest.json） | 导出包可还原项目全貌 |
| F5.4 | 备份策略：`data/` 目录定期 git 快照备份（使用手册给出命令） | 手册含备份/恢复步骤 |

### F6 评测体系

| ID | 需求 | 验收标准 |
|---|---|---|
| F6.1 | 四维 evaluator：需求符合度 30% / 可运行率 30% / 规范符合度 20% / 架构合理性 20% | 每维独立实现、可单测 |
| F6.2 | 双门槛通过判定：total ≥ 75 且 runnability ≥ 60 | 判定逻辑与报告一致 |
| F6.3 | 证据链：每分附 evidence（文件/行号/命令输出/judge 理由）；judge 结构化输出 + 低温（≤0.2） | 抽查报告证据可定位 |
| F6.4 | 批量跑分：同一 suite 对不同模型路由组合跑分，输出性价比榜单（total_score vs cost_cny） | ≥2 任务批量对比可复现 |
| F6.5 | 测试来源：QA 角色生成测试 + 支持人工挂载 `/tests` 目录（约定路径优先） | 两种来源均可跑 |

### F7 模型网关与成本控制

| ID | 需求 | 验收标准 |
|---|---|---|
| F7.1 | OpenAI 兼容多 provider：DeepSeek 先行（deepseek-reasoner=planner / deepseek-chat=executor）；Qwen/GLM/Kimi/Ollama/vLLM 加配置即接入 | 配置切换生效 |
| F7.2 | 分级路由 + fallback：planner 走推理模型、executor 走快模型；失败按优先级链重试 | 路由命中与降级有日志 |
| F7.3 | BudgetGuard：单 run 50 万 token、全局日成本 ¥50（`config/models.yaml` 可调）；超限 run 暂停 + SSE 告警 | 超限路径单测覆盖 |
| F7.4 | UsageRecorder：每次调用计量（provider/model/tier/tokens/cost/latency）落 `model_calls` 表 | 用量页可查 run/project/global 三 scope |

### F8 沙箱执行

| ID | 需求 | 验收标准 |
|---|---|---|
| F8.1 | Sandbox 接口：start / stop / destroy + exec / read_file / write_file / list_files / set_network_policy | 接口可单测（mock） |
| F8.2 | DockerSandbox：`python:3.12-slim` 镜像；限额 `--cpus=2 --memory=4g --pids-limit=512`；默认无网络，评测按需 restricted（pypi 白名单） | 资源限额生效；网络策略可切换 |
| F8.3 | 会话管理：每 run 一个会话，工作区 = 该 run 代码产物目录 | 会话与 run 一一对应，可追溯 |

### F9 Web 控制台（Vue3 + Element Plus + Pinia）

| ID | 需求 | 验收标准 |
|---|---|---|
| F9.1 | 页面六件套：项目看板 / 运行详情 / 产物库 / 审批中心 / 评测报告 / 设置 | 浏览器全流程可走通 |
| F9.2 | 核心组件：StageStepper / LogStream / ApprovalCard / MarkdownView / DiffView | 各组件在对应页面渲染真实数据 |

### F10 实时事件与可观测

| ID | 需求 | 验收标准 |
|---|---|---|
| F10.1 | SSE 事件流：run/stage/approval/artifact/message/usage/budget/evaluation 八类事件 | 前端实时渲染 |
| F10.2 | 断线重放：`Last-Event-ID` 补齐缺口事件 | 断线重连后无丢事件 |
| F10.3 | 消息流面板：角色间消息按 seq 顺序渲染 | RunDetail 页可见 |

### F11 断点恢复与容错

| ID | 需求 | 验收标准 |
|---|---|---|
| F11.1 | 每步 checkpoint 落库（阶段结果 / 等待态 / 审批决策） | 状态转移即有记录 |
| F11.2 | 启动恢复：扫描未完成 run——running 标记中断并从当前阶段 attempt+1 重跑（已产产物保留为历史版本）；waiting_approval 原地恢复 | 杀进程重启后 run 自动恢复，产物不丢 |
| F11.3 | 阶段失败保留现场（阶段记录 + 已产产物），可 retry-stage 或整卷重来 | 失败 run 可恢复 |

## 五、非功能需求

### N1 环境兼容性（Win10 / Win11 双兼容）

- **目标机**：Windows 10（Build 19041 及以上）或 Windows 11；均通过 WSL2 后端运行 Docker Desktop；Python 3.12 + uv
- **Win10 注意**：需手动安装 WSL2（使用手册给出 `wsl --install` 与版本检查步骤）；Build < 19041 的老系统走降级路径
- **Win11 注意**：WSL2 原生支持，开箱即用
- **启动前检查**：使用手册提供版本与 WSL2 状态检查步骤（`winver` / `wsl --status`）
- **降级路径**：WSL2/Docker 不可用时启用 `LocalSandbox`（subprocess + 资源限额），隔离性降级但流程不中断；不阻塞 T01-T05 主线
- **跨平台备注**：运行项目的电脑环境可能因人而异（演示、分享、换机）——技术栈（Python + Docker + 前端）不绑定 Windows，macOS / Linux 安装 Docker Desktop 后同样可运行；沙箱资源限额参数按平台配置调整

### N2 性能

- SSE 事件端到端延迟 < 1s（本机）
- 单 run 耗时取决于 LLM 响应，无硬性指标；评测 harness 记录 `wall_time` 供优化参考

### N3 成本控制

- 默认预算：单 run 50 万 token；全局日成本 ¥50（`config/models.yaml` 可调）
- 超限行为：run 暂停 + SSE 告警；人工提额或改路由后恢复

### N4 安全

- 密钥只走环境变量（`.env`，不入库、不入日志、不进产物）
- 沙箱默认无网络；生成的代码一律视为不可信
- API 单机 token（`X-API-Token`）；CORS 仅放行 localhost

### N5 可恢复性

- 见 F11；SQLite WAL 模式；`data/` 目录备份策略见 F5.4

### N6 可扩展性（可持续升级）

- 协议化扩展点 E1-E10（LLM 适配器 / 沙箱适配器 / 执行引擎适配器 / 角色 / 流水线 / 评测器 / 导出 / MCP-A2A / 存储 / 部署形态）：**新增能力 = 新增一个实现类 + 一行配置，不改内核**
- 兼容性防线：REST API 版本化（`/api/v1`，破坏性变更升 v2）；产物版本不可变；配置 YAML 带 version 字段；事件协议只增字段不删字段

## 六、UI/交互概要

### 6.1 页面清单

| 页面 | 核心内容 |
|---|---|
| 项目看板 ProjectBoard | 项目卡片；发起运行入口（需求输入 + pipeline/mode 选择）；最近 runs 状态 |
| 运行详情 RunDetail | StageStepper 阶段进度；SSE 日志流；消息流面板；运行 context 查看 |
| 产物库 ArtifactLibrary | 按项目/类型分组；版本列表；Markdown 渲染；代码文件树；版本 diff |
| 审批中心 ApprovalCenter | 待审卡片（阶段摘要 + 产物 + 历史反馈链）；通过 / 驳回（驳回必须填反馈） |
| 评测报告 EvalReport | 四维分数；证据链；通过判定；成本；历史报告对比 |
| 设置 Settings | 模型 provider / 路由 / 预算查看（脱敏）；沙箱状态 |

### 6.2 关键交互

1. **发起运行**：填需求 → 选模式 → 202 返回 → 自动订阅 SSE → 阶段推进实时可见
2. **审批**：卡片展示待审产物（PRD/设计用 Markdown；代码用文件树 + diff）；通过直接流转；驳回必须填反馈，回流目标角色重跑
3. **版本 diff**：按文件分组的 unified diff，任意两版本可切换对比
4. **导出**：整库 zip + manifest.json，可还原项目全貌
