## 1. 现状与问题证据

### 1.1 ★2 整文件回退（docs/14 §3.2-★2 + 代码级定位）

三段式处置在 `role_executor._execute_with_patch_contract`（`src/ymir/orchestrator/role_executor.py:325-490`）：

- 第一段（:407-423）：按模板策略合并（默认 `reject`），命中即抛 `SymbolRegressionConflict`；
- 第二段（:425-430，重试）：模型重新规划后再次合（仍 `reject`）；
- 第三段（:431-490，兜底）：重试仍冲突 ⇒ 把 `on_protected_hit` 与 `symbol_deletions` 同时降级为 `ignore`（:445 `fallback_symbols = "ignore" if symbol_policy == "reject" else symbol_policy`、:450-451 `symbol_deletions=fallback_symbols`）。

`symbol_deletions="ignore"` 的语义（`artifacts/merge.py:700-703` docstring）：**"丢弃模型内容、保留基线版本"** ⇒ 整文件回退。

**后果（docs/14 §3.2-★2）**：模型若在某个 `.py` 文件里**既做了正当重构、又误删了一个仍被引用的公共顶层符号**，第三段兜底会把**整文件**回退成基线版——正当重构一起被吃掉，只剩一条 `symbol_regression_ignored:1` 警告。这正是"尺子校准后量出来仍不合格"的最深层原因。**v1.3.1 真跑 R-b / R-c1 / R-c2 三个 run 全部命中**（命中文件：`ymir_cli/stats.py`、`app/main.py` 等）。

**根因**：回退粒度是"整文件"，不是"符号"。

### 1.2 ★3 提升质量传染（docs/14 §3.2-★3）

`POST /projects/{id}/baselines/from-merge`（`src/ymir/api/routers/artifacts.py:362-450`）→ `promote_merged_to_baseline`（`artifacts/provenance.py`）。现状：**不校验**即将成为新基线的合并树的健康度。（实现后的判据是**合并树自身**的 `blocking_failed` / `regression`，**不是**这里的 `baseline_runnability` —— 后者探的是上一轮基线，见 §3.2 返修 1。）

**后果（docs/14 §3.2-★3）**：坏补丁（前端构建坏的——R-c1 前端构建就是坏的，**v2 因此也坏**，且探针如实报 `unhealthy`）被提升成新基线 ⇒ 喂下一轮。语义必然，非 bug，但必须在闸门处拦截。

### 1.3 P2 三项（docs/14 §7.1）

- **W3 `skeleton_filled` 真跑零覆盖**：`build_probe_tree`（`evaluation/baseline_probe.py:246-308`）的两个真跑基线都含全部骨架 ⇒ 走 `raw` 短路分支（:290-295、:306-307），`skeleton_filled` 路径（:297-308）从未被真实数据触发，只有纯函数级证据（`probe_skeleton_fill_demo.txt`）。
- **W4 `sample_markers` 噪声**：`_collect_markers`（`evaluation/attribution.py:306`）收集标记时未过滤 Python 标准库绝对路径（如 `.../site-packages/...`、`.../Lib/...`），报告里出现与本次生成无关的路径噪声；且生成的产物 `code.json`（定位 `report`/`store` 写 code.json 处）未记账 markers。
- **W5 `ruff` 掩盖框架惯例**：FastAPI 模板用骨架 `ruff.toml` 的全局 `ignore = ["B008"]`（`config/templates/fastapi-vue3.yaml:86`）+ 检查命令 `ruff check --ignore B008 .`（:127）掩盖 FastAPI `Depends()` 框架惯例（`docs/14` 建议改 `per-file-ignores`，仅对用 `Depends` 的路由文件忽略，而非全局忽略）。
  - ⚠ **口径修正（来自产品经理增量 PRD）**：`docs/14` §7.1 称"5 个模板都带此参数"，但仓库 `config/templates/` 实际只有 **4 套**（python-cli / fastapi-vue3 / data-pipeline / node-express），且 `B008` 全文仅出现在 `fastapi-vue3.yaml`（:81-88、:121-127）。**改造范围以仓库实际为准**——仅 FastAPI 模板需要 per-file-ignores 改造，其余 3 套无 `Depends` 惯例、本就不带 B008。

## 3. 设计

### 3.1 ★2 符号级回退（T1）—— 核心改动

**思路**：回退粒度从"整文件"细化到"符号"。

- **`symbols.py` 新增纯函数 `revert_symbols(base, patch, removals) -> dict[str, str]`**：对 `removals`（`detect_symbol_removals` 的结果）中每个 `(path, symbols)`，从 `base[path]` 取出这些公共顶层符号（`def`/`async def`/`class`）的源码文本（按 AST 节点 `unparse` 或保留原始源码区间），插入回 `patch[path]`（不重复插入；保留模型对同文件其它部分的编辑）。纯函数、零 IO、绝不抛异常（沿用 `symbols.py` 三条纪律）。
- **`merge.py` 校验新增 `"revert"`**（与 `off`/`reject` 并列，`merge.py:736` 附近）；命中时不再"丢弃整文件保留基线"，而是"保留 patch、还原被删符号"。重写 `merge.py:700-703` 的 `symbol_deletions` docstring。
- **`role_executor.py` 第三段（:445）改为**：`fallback_symbols = "revert" if symbol_policy == "reject" else symbol_policy`；`:450-451` 的 `symbol_deletions=fallback_symbols`。**`revert` 仅作运行时兜底值**：`templates/models.py` 的 `symbol_deletions` 字段仍只允许 `off`/`reject`（不允许模板声明 `revert`，避免默认就回退）。
- **兼容性**：模板声明 `off`/`reject` 时行为与 v1.3.1 **逐字节一致**（revert 只在"reject 撞两次墙"后才被用）。v1.3.1 §8 的 A9 逐字节一致契约（23 例 × 四产物）不受影响，因为 revert 是 runtime 降级路径、默认配置不触发。

> **★ 返修（v1.4 QA 对抗验证 · ROUTE: Engineer · P1-2）**：首版把还原的定义**固定追加到文件末尾**，  
> 实测比 `ignore` 的整文件回退更糟（树仍是坏的）：`if __name__ == "__main__": main()` 结尾的文件里  
> 被还原的符号在调用点之后才定义 ⇒ `NameError`；`@app.get("/tasks")` 路由在 `include_router(...)` /  
> 模块级自检之后才执行 ⇒ **路由静默丢失**；`__all__` 也删了该符号时不补 `__all__` ⇒ `from mod import *`

5. **`revert` 不可写进模板**：仅运行时第三段兜底，模板声明面仍限 `off`/`reject`/`ignore`，`reject` 是三段式的入口。
