### 必须如实标注的七条边界

> 不写这七条，"三项达成"就是过度声称。

1. **A8 的真跑未重做。** v1.5 真跑期间补评测被传了占位 `requirement`，导致同一棵树的 `total_score` 是 92.65（gate）vs 62.65（补评测），差值恰好 `0.3 × 100 = 30`。根因已在修复轮修掉（有归属 run 时忽略调用方 `requirement`，报告新增 `requirement_source`），但**修复后的 A8 真跑没有重跑**：现有结论只到夹具层（`test_supplementary_eval_matches_gate`，HTTP + FakeJudge，确定性字段逐字段相等）。"同尺"在真实 judge 下的验证仍是空白。
2. **A7 按约定降级为夹具级。** 要真验"镜像缺 `node-build`"必须重建镜像删工具链，成本与收益不成比例；且 `node-build` 实际**在**镜像里（`docker/sandbox.Dockerfile:77`）。
3. **A15「默认不返修」只有源码级断言 + 运行台账，没有行为用例。** `test_cli_default_does_not_repair` 是 `inspect.getsource` 断言。
4. **U1 镜像能力边界未解。** 镜像只装了 `express/typescript/@types/*` ⇒ 真实 Vue 前端的 `fe-build`、node 树的 `node-build` / `node --test` 在本镜像下**只能"未验证"**。D-3 修复保证 `tsc` 这条 D2 能真跑，但 D1 仍不可达。
5. **U3「回归未检查」只做披露，不根治。** 只有项目维度补评测报告时，仅 D3 回归的树**仍会 201**，只是多了 `baseline_promoted_regression_unknown:1`。根治要把 `baseline_ref` 引进项目维度，属 v1.6。
6. **U4 `criteria_diverged:1` 没有真跑取证。** 需要"胜者宽松 + 败者严格"的两份报告组合，本批轮次/预算未覆盖；夹具层已双向钉住（后端 2 例 + 前端多码 3 例）。
7. **N2 是一条经裁决的口径例外。** 真实 node 树声明 `lodash`（镜像没有）⇒ `npx tsc --noEmit` 仍执行 ⇒ 报 `TS2307`、exit=2 ⇒ 进 `blocking_failed` ⇒ **判不可交付**。这与 PRD T1-R2「环境缺失一律 skipped、不阻断」字面冲突。裁决接受，理由与代价见 `docs/17` §7.3-N2；v1.6 评估 `--noResolve` 能否规避。

`_report_health_status` 绑定的是"报告**自称**的 criteria"。本地产物可人工改写 —— 这条判据防的是**串味**，不是**伪造**。要防伪造需签名，不在本版。

### 6.2 v1.4 存量产物/报告全部失效

模板 YAML 已改 ⇒ `template_hash` 变化 ⇒ v1.4 遗留的待提升 patch 产物提升时会被 **1003「模板已变更」** 拒（`provenance.py:477-481`）；v1.4 风格报告无 `criteria_source` ⇒ 视为弱口径 ⇒ 409 `unknown`。两者都需要**用当前模板重跑一轮 / 重评一次**。这是 v1.5 方案生效的必然代价，发版说明已写。

### 6.3 镜像能力决定"能验什么"

镜像只有 `express/typescript/@types/*`。真实 Vue 前端、真实 node 树的构建与测试都会因依赖缺失判 `unverified`。这不是代码问题，但意味着**前端构建这条判据在当前镜像下形同虚设**（U1）。要真正验证需要在镜像里补 `vue`/`vite` 及相关依赖。

### 6.4 补评测的 judge 成本仍不归属任何 run

`POST /evaluations` 的 `model_calls.run_id` 仍为 `NULL`（v1.4 §6.5 的既有口径，本版未改）。按 run 统计成本时，补评测那部分仍是"未归属调用"。

### 6.5 `unverified` 的触发粒度是"组 × 档"

某组某档一条都没执行才算未验证。**探针部分执行**（1/N 真跑）仍算"回归已检查"，不披露（N-4，v1.6 加 `baseline_partial`）。
